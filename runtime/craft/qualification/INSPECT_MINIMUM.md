# Inspect minimum with editable static findings

The maintained `craft/runtime/tools/inspect_acceptance.py` fixture uses the
sealed macOS package's public CLI to exercise all six Inspect operations. It
covers owned JavaScript, WebAssembly and native containers, exact native report
preservation, independently replayed analyst annotations and portable delivery.
It never executes inspected targets or resolves their imports.

## Exact findings and precise interpretation

The JavaScript study contains an external import name and an `answer` export.
Native parser facts must match both independently authored strings. Two analyst
notes reference actual native findings. Updating one note preserves the other,
the complete source bytes, native report bytes and every previous history member.

An independent reader uses only ZIP/JSON primitives to verify every member hash,
source binding, complete annotation state and history transition. It reconstructs
notes from the typed edits and independently binds each note to the input, report
and evidence identifier. Native replay separately compares entire fresh reports,
including display fields outside the upstream canonical evidence identifier.

Standalone `.dobeinspect` import preserves the complete archive byte-for-byte.
Whole-project transfer into independent private state allows precise removal of
the two notes. Current annotations return to an empty list, while every original
finding and previous annotation state remains intact. Clearing notes does not
remove history or restore the initial archive bytes.

## Input families and readable delivery

A valid authored Wasm module exports `answer`; its integer-only canonical evidence
identity is independently recomputed. A malformed module retains explicit invalid
validation and its limitation. Deeply nested JavaScript retains the lexer fallback
and warning. Neither parser success nor job success makes target input safe.

One owned C source is compiled locally and examined as Mach-O data. The native
symbol list must contain the same authored symbol independently found by the
host symbol reader. Separate minimal ELF and PE byte fixtures have known 64-bit,
little-endian x86-64 headers. These are static container observations, not target
execution, exhaustive reverse engineering or Linux/Windows runtime qualification.

JSON delivery separates the complete native report from exact analyst notes.
HTML is parsed independently: original note text must round-trip through escaping,
active tags and external-resource attributes are absent, and the restrictive
content policy remains present. Browser rendering, visual approval and general
accessibility are not claimed by this structural check.

## Refusals and runtime boundaries

Wrong input consent, stale portable hashes, missing finding/removal targets and
an invalid multi-edit batch publish no revision and preserve the project head.
A checksum-consistent changed report summary is rejected by full native replay.
A checksum-consistent annotation state inconsistent with its edit history is
rejected by history replay. Missing consent, arbitrary paths, foreign project
assets, duplicate edits and unknown fields fail admission. A portable archive
never supplies permission on the owner's behalf.

Fresh MCP clients expose all six operations through the current eighteen-tool
endpoint and retrieve the same durable result. Both private state databases,
all native execution groups, every successful checkout receipt and the complete
sealed package are checked. Earlier cancellation, supervisor-death, reconciliation,
installation and rollback checks retain their historical artifact boundaries;
this fixture does not repeat installed-service mutations.

The first harness attempt added a redundant outer network sandbox. macOS refused
the sealed CLI's nested sandbox before a project database or durable job existed.
That pilot is retained. The corrected harness invokes the unchanged sealed CLI,
whose native guard already applies network denial to runtime and worker children.
The independent compiler and symbol reader use separate network-denied processes.
No production guard or runtime behavior changes.
