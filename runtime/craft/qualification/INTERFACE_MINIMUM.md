# Editable Interface campaign acceptance

Date: 2026-11-18. Scope: a bounded component-based campaign suite through the
installed sealed macOS ARM64 CLI and MCP. All four Interface operations are
exercised: create, edit, native import and inspection. This does not qualify the
complete application, arbitrary imported designs, Linux/Cloud or publication.

## Produced work

The fixture creates a 64 × 64 editable Vector mark and imports its exact PNG into
an Interface document. A 720 × 720 campaign board combines native Inter text,
two instances of one editable card component and the embedded mark. A separate
320 × 320 identity tile provides an untouched visual control and a nested frame
clipping fixture. Native sources, embedded artwork, previews, inspection records
and portable project receipts are retained.

The revision first gives the right card its own text. It then changes the main
component's text and fill. The left card follows those main values; the right
card keeps its explicit text overrides while receiving the shared fill. Every
native ID, component link, fixed dimension and unrelated field survives. Pixel
changes stay inside the two card regions; the identity tile remains exact.

The inspected original and revision have legible text, consistent margins,
balanced cards and the established charcoal, warm-white and cobalt palette.
The pale-blue revised fill renders at its exact requested RGB value. Agent
inspection is not owner aesthetic approval. Global clipping and publication
approval flags remain false; the fixture proves only its specified clipping
geometry and reviewed outputs.

## Executable acceptance

Run the maintained fixture with the installed package's private Python and a new
output directory. It uses that package's guarded CLI, private state and a minimal
PATH. It does not install anything, start a service, contact a remote provider or
open an editor.

```sh
"$PACKAGE/lib/dobe/python/bin/python3" -I -B \
  craft/runtime/tools/interface_acceptance.py \
  "$PACKAGE" /absolute/path/to/new-interface-evidence
```

The reusable fixture passes **64 checks** over **13 native jobs**: nine succeed
and four deliberately fail without publication. An earlier private qualification
passes 56 checks with the same job sequence. Both runs use separate fresh
states, for 26 native execution groups in total.

The checks establish:

- Exact Vector artwork embedding, decoded pixels over the requested background,
  artboard dimensions and nested frame clipping. An explicit child preview
  correctly omits ancestor clipping, matching the documented preview scope.
- Component propagation, preserved text overrides, expected override metadata,
  exact revised fill, protected native fields and unchanged identity pixels.
- Cold inspection and native import preserving the complete saved document and
  embedded image bytes, with exact output pixels.
- Portable import into fresh state. Two disconnected MCP clients replay the same
  request and receive one queued job; the separate worker executes it once.
- Editing the imported main component while preserving its instance override,
  restoring that instance to clear the override, and proving renewed propagation.
  A simultaneous footer move changes only its requested eight-pixel translation.
- Failure after an earlier valid edit in a batch, missing glyphs, an unavailable
  explicit font and an unknown native field that the parser would drop. No failed
  job publishes a revision or advances its project head.
- Every successful artifact matching its portable receipt, all earlier delivery
  bytes remaining unchanged, native process-group absence and identical native
  payload verification before and after the work.

## Independent repeat and delivery checks

Thirty-three additional checks compare the two runs and verify the handoff.
Eighteen PNG comparisons have identical dimensions and decoded RGBA pixels. The
Vector SVG is byte-identical. Eight Interface documents retain all native fields
apart from references to the independently verified Vector PNG timestamp change.

The first comparison incorrectly required equal image hashes between independent
Vector renders. The PNGs contain different `Creation Time` text chunks. A parser
verifies every PNG chunk CRC and proves all other chunks identical. Only the
corresponding image-index and image-paint hash references are normalized in the
cross-run native comparison. Within each run, all original embedded PNG bytes
remain exact. No renderer or saved artifact was changed to hide the difference;
byte-identical independent Vector PNG exports are not claimed.

The 35-file delivery contains four complete project folders, their four ZIP
archives, a comparison preview, reuse instructions and an explicitly bound recipe
template. Each archive matches every artifact hash and length in its project
receipt. Extract a ZIP before importing its project folder; the local import
command is not claimed to accept ZIPs directly. All 26 native execution groups
are absent after both runs.
