# Write minimum on the corrected PDF candidate

The maintained `craft/runtime/tools/write_acceptance.py` fixture passes **104
checks across 31 durable CLI jobs**: 25 successful operations and six expected
worker refusals. One additional request is refused at admission, before creating
a durable job. This is bounded macOS ARM64 evidence, not complete application,
Office-format, signed-installation or Local/Cloud release qualification.

## Observed behavior

The original fictional production brief uses the versioned `production_brief`
recipe, pinned Source Serif 4 and Source Sans 3 fonts, written direction and a
three-column deliverables table. The fixture exercises all six public Write
operations: create, import, inspect, edit, bundle and export.

- A single atomic revision changes wording, title color, paragraph pagination
  and page margins through all four declared typed edit kinds. An independent
  complete-model prediction permits only those requested changes.
- PNG delivery produces one-page and two-page A4 documents, explicitly ordered
  pages and fractional scaling. Cold native exports are byte-identical.
- A second-page text revision leaves the first page pixel-identical. Reversing
  that revision after a whole-project transfer into a second private state
  restores both original page rasters and the complete native model.
- Standalone `.dobewrite` import and native JSON import retain their complete
  models and exact original bytes. Inspection and bundle delivery preserve
  editable source, revision history and production records.
- PDF delivery uses the newly corrected, receipt-bound PDF engine. Each export
  receives two independent cold reads with equal complete extracted state,
  page geometry, normalized character inventories and decoded raster hashes.
  Character inventories do not prove reading order or arbitrary PDF fidelity.
- Missing requested fonts are refused unless the exact observed substitution
  is explicitly supplied. An approved fallback is recorded without changing
  the document's requested fonts.
- A caller-owned image-bearing document preserves its embedded PNG exactly.
  Independent and native picture decoders agree with zero channel error. The
  PNG page contains both expected swatch colors over the required area, and
  adding the image leaves the first page unchanged.
- Output inspection leads to a real paragraph revision adding sixteen points
  above the illustration. Only the predicted paragraph properties change.
  The final document exports to PNG/PDF and survives another portable handoff
  with equal complete models and every PNG pixel unchanged.
- Stale archive hashes, invalid selectors in an atomic batch, incorrect text
  expectations, nonexistent pages, unapproved font substitutions and omitted
  native image-layout defaults publish no revision. The four refusal cases on
  the existing main project and the font refusal leave their heads unchanged.
  Unknown top-level native fields are rejected at admission.
- Both state databases pass `quick_check`; all 31 registered execution groups
  are absent. Every successful checkout receipt still matches its files, and
  the complete sealed payload verifies identically before and after the run.

The 31 worker commands take **85.936 seconds** in total. This is observed local
wall time including package verification and validation. It is not CPU time,
peak memory, energy consumption, cloud cost or elapsed time for the whole unit.

## Preserved fixture corrections

The initial fixture expected unknown native fields to become a failed durable
job. The product correctly refuses them earlier, at admission. The final fixture
asserts that exact refusal and retains the initial error log.

The supplemental image fixture initially assumed that a text-only recipe already
contained an empty media store; that local preparation error created no job.
The next image request omitted native crop and inline-layout defaults. Complete
native comparison correctly refused its normalization. That failed job remains
in the final evidence. A separate request explicitly authors neutral cropping
and inline layout and then succeeds. No runtime or engine check is relaxed.
Completed jobs are reused when resuming; no successful operation is replayed.
