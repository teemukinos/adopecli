# Material minimum with editable procedural production

The maintained `craft/runtime/tools/material_acceptance.py` fixture exercises all
eight Material operations through the sealed macOS package. It combines two
original procedural recipes, independent raster expectations, exact source
revision checks, portable material verification and explicit refusal cases.
This is bounded application acceptance, not universal graph or photographic
rendering qualification.

The completed run passes **263 checks across 37 durable jobs**: 32
successes, 5 expected worker refusals and 4 admission refusals.
Worker commands take **95.535 seconds** in total on this local machine,
including package verification and publication. This is wall time, not CPU time,
peak memory, energy, cloud cost or total qualification elapsed time.

## Reusable source and precise revisions

The `ceramic_tiles` and `ribbed_metal` recipes create ordinary editable graphs at
256 × 256 pixels. They expose the controls in their source and retain the original
recipe and input archive. Each produces base color, roughness, metallic, height,
normal and ambient occlusion. Independent mathematical expectations cover every
PNG8 pixel in all six channels, within one 8-bit quantization step. Normals use
wrapped height derivatives; ceramic and metal use different analytic profiles.

Changing only the exposed red control preserves every other decoded physical map exactly.
An independent XML prediction compares the complete source after replacing only
the requested scalar. Every unrelated archive member, initial input, origin record
and creation recipe remains exact. Metadata insertion, replacement and removal
use hash-bound source selectors and independent complete XML predictions, then
restore the byte-identical original archive.

Portable transfer into a second private state restores the original color,
archive and all six map pixels. A fresh native preview of that restored graph
reproduces the original encoded PNG exactly. Separate archive, bare SBS and
version-2 material imports retain their own complete original bytes and the same
editable XML source. Bare SBS receives the explicit `source.sbs` archive wrapper. Native inspection and bounded cooking preserve the
current source; cooking is not relabelled as a preview.

## Deliveries and verification boundaries

Public map export exercises PNG8, PNG16, JPEG, TGA, BMP, WebP, OpenEXR and Radiance
HDR. Each reports six channel identities, bounded evaluation and complete decoding.
Lossless integer exports are compared with the independent PNG8 reference within
one quantization step. Sixteen-bit grayscale is explicitly scaled to eight bits
for that comparison; Pillow's direct grayscale conversion would clamp values.
JPEG remains lossy. Float EXR and RGBE HDR retain their explicit format, transfer
and alpha policies; their complete bounded decoding is runtime evidence, not an
additional independent all-pixel floating-point oracle. TIFF remains unsupported.

Repeated version-2 bundle exports are byte-identical and contain the exact graph
plus six PNG16 maps. Import verifies a fresh bounded native source cook. A valid
PNG16 with substituted roughness pixels is refused for disagreeing with that cook,
even though its archive and image checksums are valid. Source and maps cannot
silently become inconsistent.

The final three 768 × 768 previews use identical camera and environment settings
with actual displaced plane geometry and six material channels. Earlier previews
remain evidence. The final camera is pulled back to leave margin around the plane. Assistant
inspection confirms all boundaries are visible, equal framing across surfaces,
consistent ceramic relief and a distinct ribbed metal silhouette.
Visual inspection and owner acceptance remain distinct from numeric validation;
these are procedural material inspections, not general photographic images.

Stale source hashes and scalar expectations, an invalid edit batch, absent graphs
and substituted portable maps publish no revision and preserve the project head.
Unsupported formats, undersampled recipes, cross-project assets and arbitrary
commands refuse admission. Fresh MCP clients discover the same eight operations
and retrieve durable CLI results. Database integrity, native process-group cleanup,
complete checkout receipts and the package seal are checked.
