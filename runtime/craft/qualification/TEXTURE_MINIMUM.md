# Texture minimum with editable material handoff

The maintained `craft/runtime/tools/texture_acceptance.py` fixture exercises all
eight public Texture operations through the sealed macOS package. Two Material
operations produce the real editable graph and portable bundle used by the
handoff. This is a bounded surface-authoring and compute qualification, not
universal native fidelity or a photographic-rendering claim.

The completed run passes **103 checks across 30 durable jobs**: 21
successes, 9 expected worker refusals and 3 separate admission refusals.
The local worker commands take **124.611 seconds** in total, including package
verification and publication. This is wall time, not CPU time, memory, energy,
cloud cost or total qualification elapsed time.

## Precise source and map revisions

A calibration plane contains a blue base and a half-opacity red finish. An
independent all-pixel expectation establishes the linear composite's sRGB export.
A roughness-only edit changes that channel while every other encoded map remains
exact. A Unicode rename preserves all maps. Source, projection, blend and
visibility revisions exercise the remaining typed properties. Complete native
project predictions constrain changes to requested slots; every unrelated
embedded member, original source and creation recipe remains exact.

Portable transfer into independent private state reverses the changes, recovering
the complete original model and every original map byte. Inspection, explicit
export and native import preserve the admitted source. Native import also retains
all baked payloads. Fresh MCP clients discover the same eight operations and
retrieve durable CLI work after client disconnection.

The first combined revision used integer JSON preconditions for native floating
values. The runtime correctly refused that request. The fixture preserves this
failed job and submits a separate request with exact native scalar types. It does
not relax comparison or modify the rejected request. A separate fixture-resume
correction compares recorded before/after heads at the time of an already finished
refusal, rather than comparing an old head with later successful work. Initial fixture
failures remain in the evidence; no production adapter changed.

## CPU computation and managed Material handoff

A 16 × 16 plane bake produces tangent normals and ambient occlusion. Independent
float expectations check every value against planar geometry. The admitted
allocation is 4,144 bytes and 512 nominal ray-work units. A partial rebake retains
the unrequested normal payload exactly. These counters are admission quantities,
not measurements of CPU seconds, peak memory, energy or cloud price.

A real `ceramic_tiles` Material recipe creates an editable graph and a version-2
portable bundle. Texture verifies a fresh Material cook before adding the linked
fill. The exact graph, bundle and previous source remain portable; unrelated
layers and resources remain intact. Replacing the linked fill with the same
material reuses owned resources and preserves the complete native document and
map bytes. A second private state exports the linked material without depending
on the first state's asset identifiers.

The sphere substrate and ceramic surface use the same 768 × 768 CPU preview
settings, camera, 64 samples and four bounces. Each render is repeated after a
cold native reopen, with identical encoded PNG and decoded pixels. Previewing
leaves the complete native source and resource payloads unchanged. Assistant
inspection confirms unchanged framing, visible ceramic grout/relief and reduced
grain compared with the earlier 384-pixel, eight-sample pilot images. Sampling
steps from the 128-pixel source maps remain visible. These images are bounded
material inspections; owner visual acceptance remains separate.

## Refusal and release boundaries

Stale and incorrectly typed preconditions, an invalid edit batch, partial bake
resizing, absent high-poly geometry, a missing camera, stale material hashes and
replacement of an ordinary layer publish no revision and preserve the head.
Rendering an older sphere revision also refuses publication after the head has
advanced. A separate explicit portable import forks that original substrate for
the final comparison preview; the existing project is not rewound.
Excessive preview work, arbitrary commands and duplicate edits refuse admission.
Database integrity, native process-group cleanup, all checkout receipts and the
entire package seal are checked.
