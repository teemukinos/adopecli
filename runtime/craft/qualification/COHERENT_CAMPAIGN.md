# Coherent campaign qualification

This unit uses the retained A dope CLI identity and native construction hero to
qualify one coherent launch kit through the sealed public CLI. It preserves the
separate twelve-second announcement and fifteen-to-seventeen-second film
requirements. Neither is replaced by the earlier ten-second ring.

## Current fixture stages

`craft/runtime/tools/coherent_campaign_acceptance.py` accepts an exact verified
construction package, a private output directory
and the retained original native hero checkout. It does not use mutable checkout
adapters to author media. The selected guard and seal are checked explicitly.
An independently authenticated verification record is required through
`--expect-verification`; the package must match it exactly. This does not turn
a caller-supplied record into publisher authentication.
The hero's complete project receipt and supplied-logo bytes are checked before
local whole-project import. Import is byte admission, not native cold reopening;
a subsequent public `construct.verify` job supplies that separate evidence.

The `socials` stage produces three native reframed compositions: 1080 × 1080,
1080 × 1350 and 1080 × 1920. It uses explicit typed parameter revisions and
full-size native renders. All twenty named objects, actual native geometry,
editable packed text, original logo bytes and complete project receipts are
checked. These are native layouts, not crops of the original raster image.
Actual pixels at all four frame centers and visible logo ink in its requested
box independently check rendered placement. Correct metadata and output size
alone are insufficient: the earlier orthographic width-only camera passed those
checks but cropped portrait compositions. The corrected AUTO camera uses the
larger canvas dimension and validates its real projection and transform. Old
incorrect portrait sources are refused by native verification; they are not
silently accepted as a valid canvas.
The first camera-corrected candidate exposed a separate refusal defect: Blender
reported Python assertions but exited zero, allowing a retained inspection to
masquerade as fresh verification. Every invocation now requests a nonzero Python
error exit and removes the previous inspection before starting. A new inspection
is required even after exit zero. The unexpected published success remains
evidence; only a rebuilt candidate can establish corrected refusal behavior.
Each aspect ratio and the announcement use independent imported projects so
their revision heads do not compete. The first fixture correctly received a
stale-head publication refusal when it attempted a second sibling on the square's
advanced project. That failed job remains preserved; the successful square is
reused, and subsequent variants have their own explicit project histories.

The `announcement` stage preserves nineteen native objects and animates only
the selected strip. Its vertical position stays at 540 through frame 72,
interpolates linearly to 595 at frame 84, and remains there through frame 287.
The result must be a full 1920 × 1080, 24-fps, twelve-second H.264 movie. It is
explicitly silent. The fixture independently checks the stream and decodes all
288 frames. Each decoded frame must place the selected strip within two pixels
of its expected vertical center; mean RGB error in the fixed typography/logo
region must stay within 1.5 levels against the native still. H.264 is lossy, so
this comparison does not claim byte-identical pixels. The decode has a bounded
six-minute deadline and no network access.

Each durable request has a stable key and retained outcome. `--resume` reuses
recorded successful work; an existing active attempt requires observation and
reconciliation, and a failed attempt does not silently become a new job.
Interruption/cancellation acceptance itself remains a separate campaign stage.
Run the socials stage first, inspect its actual outputs, then resume the same
output with the announcement stage. Long native renders run through the normal
local worker and its process-group, resource and offline boundaries.

## Remaining full campaign scope

The fixture stages above do not establish the complete campaign gate. Remaining
work includes the brief's exact cold headline revision, bounded scene replacement,
usage accounting, the distinct three-shot fifteen-second film and seventeen-second
ending revision with actual audio, deterministic interruption/recovery, fresh-state
reproduction of completed delivery and owner visual/audio acceptance. The current
local directory import is distinct from the designer-owned hosted ZIP replay work.

The pinned Blender and supporting media executables are existing host inputs,
not a claim of clean-machine availability or bundled redistribution. The macOS
image is an ad-hoc rehearsal. Signing/notarization, stock-host installation,
complete dependency/source/rights closure, actual Linux/Cloud execution and
commercial gates remain open. No model API, provider, remote worker, editor
window, service installation or public publication is part of this fixture.
