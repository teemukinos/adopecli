## Local packaging evidence and release boundary

The development application bundles two engines, Python and Pillow. Real native macOS image/vector jobs have run through its independently supervised LaunchAgent with a minimal `/usr/bin:/bin` PATH, no Studio account, and the OS network deny policy. Submission while stopped remains queued and succeeds after starting the service. Native revisions survive export/import into a different project. This is stronger than source-only packaging, but it is not a clean-machine or signed-release test.

The initial package candidate wrote Python bytecode into the signed-content inventory and was rejected by its own verifier. Disabling bytecode writes corrected that failure. A later candidate attempted to use macOS's setuid `/bin/ps` inside the sandbox and failed closed. The current implementation uses the public libproc API; native jobs then passed. Retain the failed receipts and subsequent passing evidence under `.verify/` rather than deleting that history.

See local/README.md (`craft/local/README.md`) for remaining signing, installation, lifecycle and platform gates. Neither a successful local package nor workspace predicates in SQLite prove authenticated hosted tenancy, private object storage, isolated customer workers, quotas or commercial usage accounting.
